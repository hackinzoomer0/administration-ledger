# Administration Ledger scheduled tasks

The Linux user timers run these prompts locally through the headless Codex Remote daemon. Each run starts a new chat. Open Remote in the ChatGPT mobile app to view the chat. The timezone is America/Chicago. Before starting a weekly review, the runner requires a successful daily review for that Central date. After each review, the runner publishes changed public event rows to GitHub Pages and verifies the live dashboard before applying the staged ledger.

## Daily event review

Schedule every day at 7:00 a.m.

> Read ledger-owner-redacted.json in this project. Read and execute the stored nominee-review prompt alongside the factional review, using one shared news intake and evidence-linked analysis in both directions. Append the required nominee snapshot even when estimates are unchanged. Use the stored collector, watch, sources, and short analysis-rules entries to review consequential developments since the last successful daily run. Use enrich for consequential items that need readable evidence and slicer to identify existing episodes, including nearby dates and bundled rows. Prefer primary sources. At the start of every daily intake, check major scheduled outcomes and pending decisions across all tracked issues, including elections, chamber control, major court rulings, and changes in executive or military policy. Check directly for results after a major event. Record each outcome as reviewed, pending, or unreviewed. Keep pending results on the next run’s watchlist. A focused intake must state its scope and flag any major unreviewed event in its summary. After a major shock such as an election loss, search for consequential actors’ public reactions, private blame, leadership or job pressure, and counter-moves. Look beyond the result and official releases. For each material finding, record the source and attribution. Carry open contests forward for follow-up. For each material reaction, compare the actor’s prior stance, timing, target audience, and incentive. Ask what the move gains now in electoral positioning, agenda control, or protection from blame. Record a grounded strategic advantage or vulnerability when it matters, and distinguish it from a later change in votes, policy, or personnel. Treat a public move and attributed private reporting at their respective evidence levels. Distinguish authority, implementation, access, political representation, and outcomes. Update the local ledger only where the evidence changes a finding. Keep passing mentions in event context. Use db-shape and targeted validator checks for changed rows, then record scope, sources, changes, unresolved claims, and validation in collections.runs. A zero-change run can be complete. Save local changes atomically and check that the ledger has not changed since you read it before replacing it. The final daily message must include all five nominee estimates, percentage-point changes, reasons, faction/nominee implications and gaps; explicitly confirm no nominees were added and label the estimates conditional on the authorized roster. The runner publishes approved public event changes after this research turn and then requests the final report in the same chat. Treat this initial response as intermediate; the final report must enumerate every change and confirm publication.

## Weekly faction and evidence review

Schedule Mondays at 10:00 a.m.

> Read ledger-owner-redacted.json and the latest daily run logs. Read the stored nominee-review prompt; audit nominee estimates and their factional evidence links alongside the weekly faction review, appending a snapshot for any nominee changes. Use auditor-monday, recall, challenger, and the short analysis-rules to review consequential decisions from the preceding week and test prior high-impact conclusions against later evidence. Look for coverage gaps, duplicate credit, stance changes, power and financial motives, and whose interests had a channel into each decision. Before closing a major-shock review, challenge one missed strategic beneficiary or rival and ask whether the analysis mistakenly waits for a formal outcome before recognizing a shift in position. Flag blame-shifting and job pressure separately from actual personnel changes. Validate and apply supported local corrections. Log what changed, which claims remain unresolved, and what evidence would settle them. Save local changes atomically and check for intervening edits before replacing the ledger. Prepare a reviewable public update if warranted, limited to approved dashboard fields and screened for the owner's name and private source material. Keep research notes and unpublished material out of event fields. The runner handles dashboard publication.
